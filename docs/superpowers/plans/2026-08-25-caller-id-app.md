# iPhone Caller-ID App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Forwarded inbound calls show `Deal:/Opp:/Lead: <name>` on the rep's native iPhone call screen via a Call Directory extension fed by a CTI directory snapshot.

**Architecture:** Server side, a 30-minute worker sweeps Salesforce (describe-driven Deal__c phone fields; Lead Phone/Mobile; Opportunity primary-contact + Account phones), normalizes to E.164, dedupes with Deal > Opp > Lead, and persists versioned `caller_directory_entries`; device-token routes serve it paged and a pairing-code flow mints tokens from the authenticated softphone. Phone side, a SwiftUI app + CXCallDirectory extension (App Group shared store) pulls the feed and reloads the extension; background refresh keeps it current (silent push = fast-follow needing the APNs key).

**Tech Stack:** Fastify + Drizzle/Postgres (migration 0028), vitest; Swift 5/SwiftUI + CallKit's CXCallDirectoryProvider, xcodegen-generated Xcode project (Xcode 26.5), XCTest on the iPhone 17 Pro simulator.

## Global Constraints

- Label format exact: `Deal: <Deal__c.Name>` / `Opp: <Opportunity.Name>` / `Lead: <Lead.Name>`; per-number precedence Deal > Opp > Lead; numbers normalized to E.164 via `services/cti-api/src/phone.ts`'s `normalize` (invalid numbers skipped, never fatal).
- Migration is `0028_caller_directory.sql`, additive/idempotent.
- Device tokens mirror `sessions` (sha256 hash stored, revocable); pairing codes: 6 digits, 5-min TTL, single-use, hashed at rest.
- The feed is device-token-auth'd, ascending-by-e164 pages of ≤10,000; `?since=<version>` returns `{ unchanged: true, version }` when nothing changed.
- Salesforce unavailability never crashes the worker (skip the cycle, warn once) and never serves a partial snapshot (build into a fresh version, publish atomically).
- iOS: extension entries MUST be added in ascending numeric order; store shared via App Group `group.com.gghomes.cti`; no third-party iOS dependencies.
- Verify each server task with `npm test` + `npm run typecheck` in services/cti-api; iOS tasks with `xcodebuild test` on the iPhone 17 Pro simulator (project generated by xcodegen — install via `brew install xcodegen` if missing).
- The live call-screen label check requires a physical iPhone → it is the user's TestFlight acceptance, not a plan gate.
- `.claude/launch.json` is an unrelated pre-existing unstaged deletion — never stage, restore, or commit it.

```ts
/** The caller-ID directory rule (spec 2026-08-25): one label per number, the
 *  latest stage wins (Deal > Opp > Lead), stage spelled out in the label. */
import { createHash } from 'node:crypto';

export type Stage = 'deal' | 'opp' | 'lead';
export interface RawEntry { e164: string; name: string; stage: Stage }

const RANK: Record<Stage, number> = { deal: 3, opp: 2, lead: 1 };
const PREFIX: Record<Stage, string> = { deal: 'Deal: ', opp: 'Opp: ', lead: 'Lead: ' };

export function mergeDirectory(entries: ReadonlyArray<RawEntry>): Array<{ e164: string; label: string; stage: Stage }> {
  const best = new Map<string, RawEntry>();
  for (const e of entries) {
    const name = e.name.trim();
    if (!name) continue;
    const cur = best.get(e.e164);
    if (!cur || RANK[e.stage] > RANK[cur.stage]) best.set(e.e164, { ...e, name });
  }
  return [...best.values()]
    .map((e) => ({ e164: e.e164, label: PREFIX[e.stage] + e.name, stage: e.stage }))
    .sort((a, b) => (BigInt(a.e164.replace(/\D/g, '')) < BigInt(b.e164.replace(/\D/g, '')) ? -1 : 1));
}

export function contentHash(merged: ReadonlyArray<{ e164: string; label: string }>): string {
  return createHash('sha256').update(JSON.stringify(merged.map((m) => [m.e164, m.label]))).digest('hex');
}
```
